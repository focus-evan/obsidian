# 知识闭环运行规则

## 目标

让资料、知识、行动、发布和反馈拥有可验证的状态，避免“写完了”被误认为“入库了”“上线了”或“已经形成稳定知识”。

## 六阶段闭环

| 阶段 | 核心对象 | 进入条件 | 完成条件 |
|---|---|---|---|
| 1. 资料进入 | `asset-note` | 原始资产进入清单 | 分类、路径、密级完整 |
| 2. 摘要提炼 | `asset-note` / `knowledge-note` | 资料值得继续处理 | 摘要、来源、适用边界完整 |
| 3. 人工审核 | `knowledge-note` | 已形成可复用结论 | `review_status: approved` |
| 4. RAG入库 | `knowledge-note` | 已批准且允许机器检索 | 真实索引任务回写 `embedded/evaluated/approved` |
| 5. 发布交付 | `report-asset` | 形成对外或业务交付物 | 本地校验、线上状态、链接、内容哈希完整 |
| 6. 反馈回写 | `feedback` | 出现事实、风格、来源或逻辑问题 | 修正知识卡并决定是否加入评测集 |

## 状态定义

### 资产说明页

- `summary_status: pending`：尚未形成摘要。
- `summary_status: draft`：已有摘要，尚未批准。
- `review_status: approved`：人工确认可进入后续流程。
- `rag_status: pending`：仅表示尚未完成机器索引。

### 知识对象

- `workflow_stage: review`：等待审核。
- `workflow_stage: validated`：已经形成可复用结论。
- `review_status: approved`：允许进入 RAG 准备队列。
- `review_after`：到期后重新核对事实和适用条件。

### 发布对象

- `publish_status: pending`：尚未发布或尚未验证。
- `publish_status: published`：线上首次发布完成并验证。
- `publish_status: unchanged`：线上内容与本地目标一致。
- `publish_status: failed`：本地可能完成，但线上未更新。

## 不可跨越的边界

1. 生成摘要不等于完成知识审核。
2. 写入 Markdown 不等于完成 RAG 索引。
3. 本地生成 HTML 不等于已经发布到 ai-stock。
4. 代码已修改不等于数据已发布，也不等于生产已部署。
5. 反馈已记录不等于错误已经修复。

## 每周维护

1. 打开 [[00_Dashboard/知识库健康度]] 查看红黄项。
2. 从 [[00_Dashboard/资产入库队列.base]] 选择少量高价值资料处理，不批量制造低质量摘要。
3. 审核 [[00_Dashboard/知识闭环.base]] 中的知识对象。
4. 检查 [[00_Dashboard/发布与反馈.base]] 的未发布报告和未解决反馈。
5. 运行 `_ops/scripts/update_vault_health.ps1` 刷新健康度。
6. 验证完成后再推进 Codex 同步检查点和 Git 镜像。
